# PDF Arcade

21 playable games that live **inside PDF files**. No app, no install: open a PDF and play Snake, Tetris-style blocks, Minesweeper, Breakout and more.

**Play online:** https://snake-pdf.vercel.app/

## How to play

### In your browser
Open the site above and click any game.

- **Desktop Chrome, Edge, Brave or Opera:** the PDF opens in the browser's built-in viewer, which runs the game.
- **Phones, Safari and Firefox:** the game opens in a web PDF viewer ([pdf.js](https://mozilla.github.io/pdf.js/)) that runs it on the page.

### As a file
Every game is a single PDF in [`dist/`](dist/). Download one and open it in **Chrome, Edge or Firefox**.

```bash
# macOS
open -a "Google Chrome" dist/breakout.pdf
```

Viewers that don't run PDF JavaScript, like macOS Preview, most phone apps and many email previews, show the page but the game won't move.

### Controls
- **Arrow buttons** on the page work in every game that needs them.
- **Keyboard:** click the pill-shaped box that says *"click here to use W A S D"*. While it's active, W A S D act as arrows. Some games also use Space and letter keys; each game lists them under its controls.
- **Board and puzzle games** (Minesweeper, Tic-Tac-Toe, Connect Four, Lights Out, 15 Puzzle, Hangman, Word Guess, Game of Life...) let you click the squares directly.

## How it works

PDFs can contain JavaScript, originally meant for things like form validation. Chrome (PDFium), Firefox (pdf.js) and Adobe Acrobat all run it. Each game uses three PDF features:

1. **Text fields as a screen.** The game screen is a stack of read-only text fields, one per row, in a monospace font. Drawing a frame means writing a string like `"::  [][]@@  <>  ::"` into each row.
2. **A timer.** `app.setInterval("tick()", 100)` calls the game loop several times a second.
3. **Buttons and a keyboard box.** Invisible push buttons call `onArrow("up")`, `onBtn("drop")` or `onCell("m", 3, 4)`. A hidden text field catches key presses: its keystroke handler reads the key, cancels it, and passes it to the game.

The PDFs are written byte by byte by small Python scripts, with no PDF libraries. Every object, font, field and the cross-reference table is generated by hand. [`tools/build.py`](tools/build.py) is the original Snake and is the easiest place to see it all in one file.

## Project layout

```
games/
  games.json        one entry per game: title, colour, screen size, buttons, help text
  lib.js            helpers shared by every game (padding, grids, banners...)
  platform.js       glue between a game and the PDF form (drawing, input, timer)
  tetris.js ...     one file per game: just the game rules and drawing
src/                Snake's source (built by tools/build.py)
tools/
  build.py          builds Snake        -> dist/snake.pdf, web/snake.pdf
  build_games.py    builds the others   -> dist/*.pdf, web/games/*.pdf, web/index.html
  build_site.py     writes the arcade page (called by build_games.py)
  run.js            Snake's tests
  test_games.js     tests for every other game
dist/               the finished PDFs
web/                the website (arcade page + pdf.js viewer), deployed to Vercel
```

Build and test (needs Python 3 and Node.js, nothing to install):

```bash
python3 tools/build_games.py   # build every game and the arcade page
python3 tools/build.py         # build Snake
node tools/test_games.js       # play every game with random input and check the rules
node tools/run.js              # Snake's tests
```

## Make your own game

A game is one JavaScript file plus one entry in `games/games.json`. You never touch the PDF code.

**1. Write `games/mygame.js`.** It defines five functions:

```js
var G_TICK = 150;                  // ms between ticks (0 = turn-based, no timer)
var G_KEYS = { " ": "jump" };      // optional: keys that act like a named button

function gNew() {                  // a fresh game state; must have .score
  return { x: 5, score: 0, status: "ready" };
}

function gInput(s, kind, a, b, c) {
  // kind "dir"  -> a = "up" | "down" | "left" | "right"   (arrows, W A S D)
  // kind "btn"  -> a = button name from games.json
  // kind "key"  -> a = any other key, lower case
  // kind "cell" -> a, b = x, y of the clicked square, c = click group name
  if (kind === "dir" && a === "left") s.x--;
  // return a new state to replace s (e.g. restart), or null
}

function gTick(s) {                // called every G_TICK ms
  return false;                    // return true if the screen changed
}

function gRows(s) {                // what to show: one string per row
  return [mid("Hello"), mid(rep(" ", s.x) + "@")];
}

function gStatus(s) {              // the line under the screen
  return "Press an arrow";
}

// optional: function gBest(s, best) { ... }  if "best" isn't simply the highest score
```

Stick to plain **ES5** (`var`, `function`, no arrow functions, `let`/`const`, template strings or `.includes`). Acrobat's JavaScript engine is old, and this keeps games working everywhere.

**2. Add it to `games/games.json`:**

```json
{
  "id": "mygame", "title": "MY GAME", "kind": "Arcade",
  "blurb": "One line for the arcade page.",
  "accent": "#4fc3f7", "rows": 15, "cols": 40,
  "dpad": true, "buttons": [["JUMP", "jump"]], "kbd": "click here to use W A S D",
  "help": ["Short controls hint"],
  "labels": ["SCORE", "BEST"],
  "icon": ["#.#", ".o.", "#.#"]
}
```

`rows` × `cols` is the size of your text screen. For clickable squares, add a `"click"` group; see Minesweeper or Tic-Tac-Toe in `games.json` for examples.

**3. Build and test:**

```bash
python3 tools/build_games.py
node tools/test_games.js
open -a "Google Chrome" dist/mygame.pdf
```

The test script automatically fuzzes every game in `games.json` with thousands of random inputs. It fails if your game throws or draws a row wider than `cols`.

### Tips
- Cells two characters wide (`"[]"`, `"@@"`, `"  "`) look square-ish, because characters are about twice as tall as they are wide.
- Each row is a single colour, so use shapes and characters to tell things apart.
- Keep ticks at 60ms or slower, and only change what you need to. Unchanged rows aren't redrawn.
- Keep CPU opponents cheap. A search that's instant in Node can take seconds in a PDF viewer.

## Contributing

Contributions are welcome: new games, new levels or word lists, bug fixes, or reports of viewers where something breaks.

1. Fork the repo and create a branch.
2. Make your change. For a new game, follow [Make your own game](#make-your-own-game).
3. Run `python3 tools/build_games.py` and `node tools/test_games.js`, and play your game in at least one real viewer (Chrome or Firefox).
4. Commit the rebuilt files in `dist/` and `web/` too, so the site stays in sync.
5. Open a pull request saying what you added and which viewers you tried it in.

Found a bug, or a viewer where a game doesn't run? [Open an issue](https://github.com/Sanjith0524/pdf-games/issues) with the game, the viewer/browser and what happened.
